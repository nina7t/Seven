Le bug "Failed to fetch" signalé sur l'APK Sevenz est causé par le free tier de Render qui met l'app en veille après 15 min d'inactivité. Le réveil prend 30-60 secondes, ce qui dépasse le timeout de la recherche (15s). Quatre correctifs ont été appliqués dans index.html et l'APK a été rebuildé avec succès.

🐛 Bug racine — Cause du "Failed to fetch"

Critique Render Free Tier cold-start

Le proxy sur seven-hjai.onrender.com est hébergé sur le plan gratuit de Render. Après 15 minutes sans requête, l'application se met en veille. Le réveil prend typiquement 30 à 60 secondes, pendant lesquelles toutes les requêtes API échouent avec "Failed to fetch".

Vérification empirique

$ curl -m 5 https://seven-hjai.onrender.com/api/health
→ curl: (28) Operation timed out after 5001 milliseconds

$ curl -m 65 https://seven-hjai.onrender.com/api/health
→ HTTP 200 | time 3.122649s   ← OK après réveil

Le serveur fonctionne, mais le cold-start dépasse largement les timeouts appliqués côté client.

✅ Correctifs appliqués

Fix 1 Wake-up bloquant au démarrage

La barre de recherche est disabled tant que le serveur n'a pas répondu à un ping /health avec un timeout de 90s. L'utilisateur voit un placeholder clair pendant le réveil.

document.addEventListener('DOMContentLoaded', () => {
  if (!searchInput) return;
  searchInput.disabled = true;
  searchInput.placeholder = "Le serveur se réveille...";

  fetch(`${PROXY_URL}/health`, { signal: AbortSignal.timeout(90000) })
    .then(() => {
      searchInput.disabled = false;
      searchInput.placeholder = "Rechercher une musique";
    })
    .catch(() => {
      searchInput.disabled = false;
      searchInput.placeholder = "Serveur lent — réessaie";
    });
});

Fix 2 Timeout recherche → 60s

Le timeout de la recherche YouTube passe de 15s à 60s pour absorber le cold-start.

|| await fetchWithRetry(`${PROXY_URL}/youtube/search?q=...&maxResults=12`,
  { signal: AbortSignal.timeout(60000) })

Fix 3 Helper fetchWithRetry + 7 call-sites

Un helper fetchWithRetry ajoute 1 retry automatique avec backoff de 3s en cas d'échec réseau.

async function fetchWithRetry(url, options, retries = 1) {
  try {
    return await fetch(url, options);
  } catch (e) {
    if (retries > 0) {
      await new Promise(r => setTimeout(r, 3000));
      return fetchWithRetry(url, options, retries - 1);
    }
    throw e;
  }
}

Call-sites migrés :

  • Recherche YouTube principale (ligne 3631)
  • Related videos (lignes 4194, 4302)
  • Recherche 16 résultats (4819)
  • Smart tracks par artiste (5607)
  • Recherche maxResults=1 (5943, 6053)

Fix 4 Message d'erreur user-friendly

Au lieu d'afficher "Failed to fetch" (cryptique pour l'utilisateur), le catch affiche désormais un message clair quand l'erreur est réseau/timeout.

const isNet = e.name === 'TimeoutError' || e.name === 'AbortError'
              || /fetch/i.test(e.message || '');
const msg = isNet
  ? 'Serveur en cours de réveil, réessaie dans 30 secondes.'
  : `Erreur: ${esc(e.message)}`;

🧪 Procédure de test recommandée

Étape 1
Installer l'APK sur un appareil Android et lancer l'app. Le serveur Render est en veille (cold start).
Étape 2
Observer la barre de recherche : elle doit afficher "Le serveur se réveille…" et être disabled.
Étape 3
Attendre 30-60 secondes. La barre passe à "Rechercher une musique" et devient active.
Étape 4
Taper une recherche (ex. "Booba"). Les résultats s'affichent en moins de 5 secondes.
Étape 5 (optionnel)
Si Render est encore en veille au moment du tap, fetchWithRetry retente automatiquement après 3s. L'utilisateur voit les résultats sans intervention.
Étape 6 (optionnel)
Si le cold-start dépasse 60s, l'utilisateur voit le message "Serveur en cours de réveil, réessaie dans 30 secondes." au lieu de "Failed to fetch".

🚀 Améliorations futures (non bloquantes)

Les points ci-dessous sont identifiés mais non corrigés dans cette itération pour rester focalisé sur le bug critique :

Moyen Service Worker ne cache pas les API

Le SW (sw.js) n'a en cache que les assets statiques. Si le réseau tombe après le démarrage, les routes /api/* n'ont pas de fallback. Envisager un cache pour les réponses de recherche en mode "stale-while-revalidate".

Mineur Migration vers un plan Render payant

Le plan "Starter" à 7$/mois élimine le cold-start et résout le problème à la racine. À considérer si l'app est utilisée sérieusement.

Mineur Cron de keep-alive

Un cron externe (ex. cron-job.org) qui pingue /api/health toutes les 10 minutes empêche Render de dormir. Trade-off : consomme le quota gratuit d'heures.
